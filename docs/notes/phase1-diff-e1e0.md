## 2. 开拓者单位块字段定位（块 @0x46e707，47 字段，key=0xffffffff）

schema（字典反查）关键节选：`Type:8, AIType:8, Location:400, FacingDirection:8, ProcessedTurn:1,
Automation:9, Activity:8, Domain:8, …, SightPlots:400, FormationID:8, …, Components:402`。

| 字段 | E0 偏移 | E0 值 | E1 值 | 说明 |
|---|---|---|---|---|
| Type | 0x46e893 | 0xD0649D28 hash | 不变 | 单位类型定义 hash |
| **Location** | 0x46e89b | blob8=(45,6) | blob8=(43,6) | x−2，y 不变 ⇒ plot 489→487（未跨行 ✓） |
| **FacingDirection** | 0x46e8a7 | 3 | 4 | 左移后朝向改变 |
| **SightPlots** | 0x46e977 | `[7,0, 489,1, 563,1, 490,1, 415,1, 414,1, 488,1, 562…]` | 全部 plot−2 | 视野 7 格随单位平移 |
| FormationID | 0x46e9b7 | 262146 | 不变 | |

**HP 定位**：单位战斗子块（`Damage:8` 字段，Damage 块 @0x46f0c0）E0/E1 无差异 ⇒ Damage=0、
HP=100/100 保持 ✓（面板真值吻合）。HP 的直接读取路径 = 该块 Damage 字段（HP=100−Damage）。

**移动力定位**：Move 子块（`MovesRemaining:407`，@0x46e1dd 同 schema 的实例 @0x46f1c7）
E0 raw=768=3.0（面板 3/3 ✓）→ E1 raw=256=1.0（移动 2 格耗 2，剩 1/3）✓。
第二份镜像在命令缓存块（@0x46ff88，schema=Location/MovesRemaining/…/HasMoved/LastPath…）同步更新，
并 HasMoved 0→1 —— 这是 AI/指挥层的单位状态副本，读取时两处取一即可（一致）。

## 3. 操作效果 vs 重存噪音的判别

- **操作效果**（16 处）：全部与"plot −2 / x−2 / 移动 3→1 / HasMoved / 视野平移 / 朝向"自洽，
  且相互印证（单位块、命令缓存、视野表、目击表四处同时变化）。
- **重存噪音/待判**（4 处 0x87484x 计数器 ±1 + 2 处地图 flag 翻转 + 1 处计数 7→8）：
  与位置/单位无关，量级 ≤1 字节/处。0x87484b=35→36 等出现在 Controllers 容器区，
  疑为"对象处理序号/存档内部计数"，对策略分析无影响。标注待判，不编造语义。
- 未发现时间戳/随机数漂移（SyncRandom 区无差异）——该存档写入是确定性的 ✓。

## 4. 方法复现

```bash
python3 tools/blockwalk.py E0_body.bin e0.json   # 树定位
python3 tools/blockwalk.py E1_body.bin e1.json
# diff：逐字节比较 body，≤8B 间隙合并为区间；再按偏移映射到 e0.json 节点
```

差分区间到树节点的映射：0x46e89f/0x46e983 ∈ 单位块(0x46e707)；0x46f420 ∈ Move 子块；
0x47000c ∈ 命令缓存块(0x46ff88)；0x335xxx/0x33exxx ∈ 地图/视野大区（非 VariantValue 容器，
walker 记为裸区）；0x87484x ∈ Controllers 容器区。
